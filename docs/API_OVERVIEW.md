# API module overview

The public API is REST under `/api/v1`; OpenAPI is generated by FastAPI. Endpoint
names below are the target contract. The current scaffold may implement only a
Phase 1 subset and must return `404`/`501` rather than fabricated success for an
unfinished capability.

## Cross-cutting contract

- Bearer access tokens; rotated refresh token in secure platform storage.
- UUID resource IDs and server-owned `owner_id`.
- `Idempotency-Key` required for externally retried writes.
- `If-Match: "<version>"` or explicit `base_version` for mutable financial data.
- Cursor pagination: `?limit=50&cursor=...`; stable sort includes ID tie-breaker.
- RFC 3339 UTC timestamps; IANA timezone supplied where calendar intent matters.
- Consistent error body:

```json
{
  "error": {
    "code": "version_conflict",
    "message": "This transaction changed on another device.",
    "correlation_id": "...",
    "details": {"current_version": 4}
  }
}
```

Validation errors may expose field paths and safe reasons, never stack traces or
the existence of another user's resource. Responses include a correlation ID.

## Sync contract

`POST /api/v1/sync/push` accepts an ordered batch of stable operation IDs and
returns `applied`, `already_applied`, `rejected`, or `conflict` per operation.
One invalid operation does not obscure other outcomes; dependency-linked
operations are handled atomically or rejected together.

`GET /api/v1/sync/pull?after=<cursor>&limit=<n>` returns ordered changes,
tombstones, and an opaque next cursor from a consistent server-revision stream.
Clients advance the cursor only after applying the complete response locally.

## AI action contract

`POST /api/v1/ai/action-proposals` stores a validated draft and returns the exact
diff, risk level, expiry, and approval challenge. `POST .../{id}/approve` accepts
the short-lived single-use approval token. The server verifies the payload hash,
resource versions, user/session, scope, and any step-up authentication before
calling the ordinary application service. Approval is not a privileged generic
tool and cannot change the proposal payload.

## File contract

Clients request an upload reservation, upload directly to private object
storage, and finalize the metadata record. The server validates size, media type,
magic bytes, checksum, ownership, and malware policy before any processor reads
the object. Downloads use short-lived single-purpose signed URLs.

## Versioning

Backward-compatible fields may be added within v1. Breaking changes require a
new version and an overlap/migration window. Database schema version and client
minimum-supported sync protocol are exposed by the health/capabilities endpoint.
